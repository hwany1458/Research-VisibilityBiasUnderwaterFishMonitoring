# V7 rule changes (2026-11-16) — apply on top of /home/claude/coding2/CODING_INSTRUCTIONS_v2.md and the v5 codebook (/home/claude/out/Supplementary_Table_S3_Codebook_Rules_v5.xlsx)

Already in force since v5 (keep):
- V6 = NR unless the authors explicitly state performance was not evaluated by visibility, or P1 applies; N only then. V6 = Y only for classes defined by a MEASURED visibility variable; classes assigned by eye or by proxy → P.
- V1 qualitative statements count only if they describe the study's OWN imagery water clarity (not other datasets, blur, generic challenges, lighting alone).
- C1 = a detection/classification SCORE threshold used for the reported results (not cluster size, track length, NMS IoU, area, brightness).
- E3 values: 'None' / 'Point correction' (counts divided/multiplied by recall, precision, a detection rate or a regression correction factor) / 'Two-phase design-based estimate' (design-based two-phase / sampling estimator that uses human review of a probability subsample to correct AI counts, with uncertainty) / 'Observation model' (explicit model of detection probability or latent abundance). E_ALL Y requires E1 != None and (E5 independent OR E3 = Observation model).
- D: a split described only by numbers or ratios of images per set, without stating how images were assigned, is D1 = NR and D_ALL = NR. A stated random image/frame split or k-fold over images is D1 = Random images/frames or k-fold (images) and D_ALL = N (P if leakage/near-duplicates explicitly addressed).

New in V7:
1. C_ALL. Y = calibration or uncertainty evaluated as an output (C2 or C3 != None), OR false positives actually MEASURED by human verification of the system's outputs (C5 = 'False-positive rate on verified sample' or 'Both'). P = a score threshold reported and justified, OR a score-based reject/unsure option, OR duplicate-count handling by a stated mechanism (C5 = 'Duplicate-count (ID-switch) handling') without measured false positives. N = score threshold value reported as a default/unexplained choice, with no false-positive or duplicate handling. NR = no threshold and no C5. NA = classification-only study with no score threshold, no reject/unsure option and no false-positive verification.
   C5 = 'False-positive rate on verified sample' requires humans to check the system's outputs (detections, tracks, counts) on deployment/field footage and report the number or rate of false positives. Test-set precision, a confusion matrix or a false-positive rate computed against the test annotations is a standard detection metric, NOT C5.
2. R3 = Y only if the SAME trained model is evaluated on in-domain test data and on external data with the SAME metric and both values (or the change) are reported. Comparisons between different models (e.g., off-the-shelf vs fine-tuned), comparison with a value taken from another paper, or in-domain and external results on different metrics → R3 = N (R_ALL = P if R1 = Y).
3. D provider splits. If the study states it used a public dataset's predefined/official split, D1 inherits the unit documented by the dataset paper: DeepFish = random image split within habitat (50/20/30) → 'Random images/frames'; Brackish = random frame split (80/10/10) → 'Random images/frames'. D_ALL then follows the normal rule (N, or P if leakage/near-duplicates explicitly addressed). If the study made its own split of such a dataset, code the study's own description.
